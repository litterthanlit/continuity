  the runtime's measure step already knows the speed, distance and travel.

## Findings considered and rejected

- **A build cache keyed on the source hash**: not worth doing. Measured: CLI
  start-up is about 1.4 s and the build adds about 0.3 s, so there is little to save.
- **Skipping the write stage for `ct lint --fast`** (as a performance fix): the
  write stage costs about 0.15 s of a 1.8 s run.
- **De-duplicating the HyperFrames lint in `ct check`** (it runs once on its own
  and once inside `hyperframes check`): about 0.5 s of a gate that takes 20 s or
  more, and it would change where lint findings come from.
- **Building the two iterations of `ct compare` in parallel**: marginal.
- **`duration-off-token` almost never fires** (20% tolerance around ten tokens):
  an `info`-level taste call for the maintainer, not a defect to plan.
- **"An MCP write is executed"**: by design; decision 0003 lists `scenes/*.tsx`
  and `theme.ts` as writable. A clearer sentence in the tool description is a
  docs nicety at most.
- **Untrusted text in tool results and hook feedback is not delimited**: medium
  confidence and no direct code path; not planned.
- **ffmpeg opening a non-audio `music.src`**: low confidence, not tested.
- **TypeScript 7 and other routine version bumps**: no cost to waiting.
- **Shipping TypeScript run by tsx, one child `ct` per MCP call, exact pins on
  HyperFrames / three / Chrome, goldens asserted on amd64 only**: recorded
  decisions (0001–0004), not findings.
